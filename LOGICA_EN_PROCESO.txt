7. BREAK
============================================================

ESTADO: APLICADO

ARCHIVO:
aplicacion/recursos/JS scripts/usuarios.js

FUNCION:
buscar_usuario(usuarios, id)

USO:
Cuando encuentra el usuario solicitado, detiene el ciclo porque ya no es
necesario seguir buscando.

Ejemplo:

if (usuario.id === id) {
    encontrado = usuario;
    break;
}

NOTA:
En estadisticas.js todavia existe:

const visible = items.slice(0, limit);

Si se quiere reforzar el uso manual de break, se puede crear una funcion
obtener_fichas_visibles(items, limite) usando for + break y reemplazar slice.
No es necesario para el funcionamiento porque ya existe un uso real de break
en usuarios.js.

============================================================
9. WHILE
============================================================

ESTADO: APLICADO

ARCHIVO:
aplicacion/recursos/JS scripts/estadisticas.js

FUNCION:
calcular_extremos(valores)

USO:
Busca el valor minimo y maximo que se utiliza para calcular la escala de las
graficas.

Ejemplo:

let indice = 0;

while (indice < valores.length) {
    minimo = Math.min(minimo, valores[indice]);
    maximo = Math.max(maximo, valores[indice]);
    indice += 1;
}

Este es un uso real del while dentro de una funcionalidad del sistema.

============================================================
17. CONCEPTOS QUE TODAVIA FALTAN
============================================================

Luego de revisar los archivos reales del ZIP, estos conceptos NO aparecen en
el codigo propio del proyecto de forma pedagogica clara:

------------------------------------------------------------
A. DO...WHILE
------------------------------------------------------------

ESTADO: FALTA

LUGAR RECOMENDADO:
aplicacion/recursos/JS scripts/asistencia.js

o
servidor/dominio/estadisticas.js

USO PROPUESTO:
Crear una funcion auxiliar que recorra una secuencia al menos una vez y repita
el proceso mientras se cumpla una condicion valida.

Debe usarse dentro de una tarea real, no mediante prompt().

Una opcion segura seria usarlo en una funcion auxiliar de procesamiento de
estados de asistencia o de recorrido de paginas, siempre conservando el mismo
resultado actual.

Debe añadirse una prueba en:
pruebas/prueba_logica_aprendida.js


------------------------------------------------------------
B. FOR...IN
------------------------------------------------------------

ESTADO: FALTA COMO EJEMPLO PEDAGOGICO CLARO

LUGAR RECOMENDADO:
aplicacion/recursos/JS scripts/asistencia.js

FUNCIONALIDAD POSIBLE:
Recorrer las propiedades del objeto de conteos:

{
    presente: 0,
    tardanza: 0,
    ausente: 0,
    justificado: 0
}

Podria usarse para actualizar el resumen de estados.

Actualmente se utiliza:
Object.keys(counts).forEach(...)

Se podria estudiar reemplazar esa parte por:

for (const estado in counts) {
    ...
}

solo si las pruebas confirman que el resultado permanece igual.


------------------------------------------------------------
C. MATRIZ / ARRAY BIDIMENSIONAL
------------------------------------------------------------

ESTADO: FALTA

LUGAR RECOMENDADO:
aplicacion/recursos/JS scripts/asistencia.js

o
servidor/dominio/estadisticas.js

USO PROPUESTO:
Crear una matriz auxiliar para un resumen de asistencia.

Ejemplo conceptual:

filas    = aprendices o fichas
columnas = presente, tardanza, ausente, justificado

IMPORTANTE:
La matriz debe ser solamente una estructura auxiliar para calcular o resumir
informacion.

NO debe reemplazar datos/asistencia.json ni cambiar la persistencia.

Debe agregarse una prueba especifica.


------------------------------------------------------------
D. ETIQUETAS DE LOOPS
------------------------------------------------------------

ESTADO: FALTA

LUGAR RECOMENDADO:
aplicacion/recursos/JS scripts/asistencia.js

o
una funcion auxiliar de estadisticas.

USO PROPUESTO:
Recorrer dos niveles de informacion, por ejemplo:

- fichas
- aprendices de cada ficha

Si se cumple una condicion que haga innecesario revisar el resto del grupo,
se puede utilizar:

continue etiqueta_fichas;

o
break etiqueta_fichas;

Debe tener una razon funcional y una prueba.

============================================================
20. REGLA PARA LOS CAMBIOS QUE FALTAN
============================================================

Todo concepto nuevo debe cumplir estas condiciones:

1. Debe formar parte de una funcionalidad real.
2. No debe romper codigo existente.
3. No debe cambiar seguridad.
4. No debe cambiar rutas ni APIs.
5. No debe cambiar los datos persistidos.
6. Debe tener una prueba.
7. Debe poder explicarse facilmente al instructor.
